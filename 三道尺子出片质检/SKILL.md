# 三道尺子出片质检

## 核心原则

**三把尺子各管一段，绝不混算。**

同一素材，技术质检说 A 91.8、五维审美说 62.9——两个数都对，回答的是不同问题。加权平均等于把"能不能播"和"好不好看"揉成谁也说不清的数字。

| 尺子 | 问的问题 | 结果形态 |
|---|---|---|
| A 素材尺 | 这条能用吗 | 用 / 不用，**不出总分** |
| B 成品尺 | 这条片子好吗 | 0-100 + S/A/B/C/D |
| C 质检尺 | 播出去会出事吗 | A/B/C + 问题单 |

素材层**禁止给总分**。一条 9.6 秒的成品展示镜头拿五维一算就是 35.4 分"废片"，扣的全是"你只给了我一条素材"，不是素材差。

## 第 0 步：先确认尺子是真的在量（30 秒）

BRISQUE 缺模型或 opencv 不是 contrib 版时会**静默降级成 `None`**，流程照跑、分数照出，但画质判据已经失效——不查就会拿着假的干净结论去发片。

```bash
python3 -c "import cv2;print(cv2.__version__, hasattr(cv2,'quality'))"   # 必须 True
```

import sys; sys.path.insert(0, "scripts")

## 完整调用顺序

```python
import sys, glob; sys.path.insert(0, "scripts")
import aesthetic as A, qa_loop as Q

# 1 素材体检（尺子A）——每条素材一次，慢，可缓存
recs = [A.analyze(p) for p in glob.glob("素材/*.mp4")]
recs = A.rank_pool(recs)      # 打分 + 分档 S/A/B/C
A.assign_kinds(recs)          # 判角色 HOOK/BEFORE/PROCESS/DETAIL/AFTER/CTA

# 2 闸门 → 3 编排 → 4 评审 → 5 返修（自动跑到合格或收敛）
r = Q.loop(recs, target=20.0, bpm=120)
print(Q.report(r["audit"], r))

# 6 渲染（本技能不含渲染器，见"边界"）
# 7 成片重测：预测 vs 实测
t = Q.tech_gate("成片.mp4")
Q.verify_render("成片.mp4", r["plan"], r["res"])
print(Q.report(r["audit"], r, t))
```

`loop()` 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `target` | 20.0 | 目标秒数，会按叙事区间自动凑 |
| `bpm` | None | 给了就按**半拍网格**排时长，并在返回里报卡点偏差 |
| `max_iter` | 6 | 最多返修轮数 |
| `min_gain` | 1.0 | 连续两轮提升小于此值即停 |
| `verbose` | True | 打印每轮五维与卡在哪 |

**素材不足 3 条时不编排**：返回 `r["res"] is None`、`r["blocked"]` 有原因。这是设计——素材不够就补素材，不要硬凑一条片子骗自己。`report()` 会把这句话直接写进报告，不崩。

## 返回结构（别猜字段在哪）

`analyze()` 顶层是**摘要**，明细全在 `rec["shot"]` 里：

| 顶层 `rec` | 含义 |
|---|---|
| `score` / `tier` / `kind` | 素材分 / 档位 / 角色 |
| `dur` / `w` / `h` / `fps` | 时长、抽帧宽高、帧率（原始宽在 `rec["shot"]["src_w"]`） |
| `probs` / `conf` / `reasons` | 角色判别概率、置信、理由 |
| `shot` | 全部技术明细，见下表 |

`rec["shot"]` 关键字段：

| 字段 | 用途 |
|---|---|
| `score_final` | **成片口径**分数。预测和实测对账必须都用它，否则偏差假性 ±10 |
| `sharpness` | 尺度归一 + 已扣噪声的锐度 |
| `hair_detail` | 人像看这个，不是 `sharpness` |
| `brisque` / `qual_penalty` / `qual_label` | 画质三件套（成片只记录不打折） |
| `noise_sigma` / `art_ratio` / `art_penalty` / `art_label` | 噪声水平 / 跨尺度能量比 / 噪点折扣 |
| `subj_kind` / `flat_ratio` / `subject_ratio` | 介质判别：`hair`/`object`/`face`/`none` |
| `is_final` | 本次用的是哪套口径 |
| `motion` | 相机运动（抖动/甩镜），`None` = 测不出，不等于稳 |

## 尺子 A：素材体检

四条硬拒线，命中即弃，不看分数：

| 项目 | 线 | 理由 |
|---|---|---|
| 源宽 | < 720px | 输出 1080 要放大 1.5 倍，发丝必糊 |
| 抖动 | > 3.0 %W/s | 肉眼可见手抖，救不回 |
| 甩镜 | 任意 | 帧间位移过大，拼不上 |
| 细节锐度 | < 25 | 已按 `lap × (实测宽/640)` 尺度归一 |

过线后分档：≥78 主用 / 66-78 补位 / 50-66 只做 0.6s 快切 / <50 弃。

## 尺子 B：五维评审

`镜头 0.24 + 节奏 0.24 + 构图色彩 0.16 + 叙事 0.18 + 商业 0.18`，**合格线 78（A 级）**。

硬门槛（不看分，直接拦）：开头非钩子、总时长 <12s 或 >45s、缺 PROCESS / 缺 AFTER。

详细判定阈值见 `references/阈值与判定.md`。

## 卡点（BPM）

`plan_duration` 把时长吸附到**半拍网格**（整拍太粗，会丢掉 0.6s 快切的冲击力）。返修阶段改时长用的是节奏判断而不是拍点判断，所以必然会偏离网格——`loop()` 返回的 `beat` 会如实报出来：

```python
b = r["beat"]
b["max_off_ms"]     # 最大偏差毫秒
b["rows"]           # 每段的 时间点 / 第几拍 / 偏差
```

判读：**<50ms 听不出来；50-120ms 剪映里微调切点；>120ms 明显踩空，按 0.62s≈半拍 重排。**

实测：120 BPM（半拍 0.25s）下，初始编排偏差 0~50ms，返修两轮后累积到 100ms。

## 返修：照单改，不是重排碰运气

| 扣分项 | 动作 |
|---|---|
| 开头非钩子 / 首镜分低 | 池里最高分置顶，收短到 1.45s |
| 缺角色 | 池里补；没有则**复用同一素材不同入点**（开头切 1s 做钩子，结尾放完整 3s） |
| 专业证据 <3 个 | 补 PROCESS / DETAIL |
| 节奏平 | 过程压到 0.62s，成果/细节放上限 |
| 前 3 秒太静 | 首镜收短，让第二刀提前进来 |
| 总时长不够 | 拉非过程段到上限（**过程段绝不拉长**，短就是节奏武器） |
| 前后景别差太多 | 标"需重拍"，剪不出来 |

收敛：连续两轮提升 <1 分即停，最多 6 轮。修不了的如实报"素材不足 / 需重拍"，不硬凑。

## 第 7 步：成片实测对账（最容易被跳过）

plan 层分数是在**原始素材**上算的。渲染会重编码、加色校、加转场，画面会变软变偏。必须把成片按切点重新切开逐段重测。

实测规律：**静止镜头几乎不掉分，运动镜头掉 26-28 分**。只信预测会把 81.8 分的片误当成 86.1 分。

```python
t = Q.tech_gate("成片.mp4")     # {"qc":…, "veto":[…], "fixes":[…], "pass":bool}
A.analyze("成片.mp4", is_final=True)   # 成片必须带这个开关
```

## 已知缺陷（使用前必读）

1. **噪点被当成锐度（P0，已修）**：内容不变、只加噪点，锐度从 469 涨到 4255（9 倍）——劣质压缩片被判"很清晰"，手机直出反被判低分。现用三条判据联合：BRISQUE 判压缩、跨尺度能量比判噪点、20σ² 扣噪声贡献。**不要再用"先高斯降噪"的旧方案**（实测原图锐度掉 84%，低分辨率素材直接归零）。
2. 分类器没在真人正脸/侧脸素材上验证过。
3. 阈值在合成素材上标定，能证明"有区分度"，证明不了"绝对分准"。
4. 纯色背景（白墙棚拍）抖动测不出，会诚实标"未测"，不是"很稳"。
5. 返修会破坏半拍对齐，看 `r["beat"]` 而不是想当然。

详见 `references/阈值与判定.md`、`references/已知缺陷.md`。

## 依赖

```
pip install opencv-contrib-python-headless numpy
```

必须是 **contrib** 版（`cv2.quality` 里的 BRISQUE 只在 contrib 里），另有 `ffmpeg` 命令行。

BRISQUE 模型文件在 `scripts/models/`（`brisque_model.yml` + `brisque_range.yml`，共 557KB），代码用 `HERE` 相对定位，整个技能目录搬走也能跑。缺模型时降级为 `None`，不报错——但这时画质判据失效，见第 0 步。

**边界**：本技能负责"判"和"改参数"，不含渲染器（`render_plan.py` 需另配）。它输出的是 plan——每段的 `path/src_in/dur/speed/out`，交给任何渲染器或剪映草稿生成器都能用。

**成片必须传 `is_final=True`**：

```python
analyze(路径, is_final=True)   # 成片：关掉 BRISQUE 折扣
A.analyze(路径)                 # 素材：默认，开画质判据
```

不传的后果：画面上的花字/贴纸会被 BRISQUE 当成结构异常，好片从 87.6 被杀到 0.22 折。
