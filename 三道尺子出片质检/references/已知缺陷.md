# 已知缺陷

用之前先读这页。这些是已经验证存在的坑，不是猜测。

---

## P0（已修）：噪点被当成锐度

### 原来的现象

同一张图，内容完全不变，只叠加高斯噪点：

| 噪点 sigma | 裸测拉普拉斯 |
|---|---|
| 0 | 469.8 |
| 8 | 1708.9 |
| 14 | 4255.9 |

后果：抖音下载的劣质压缩片噪点多 → 被判"很清晰"；手机直出的干净原片 → 反被判低分。**方向性判反。**

### 修的过程中发现：真问题比"噪点"严重得多

拉普拉斯方差**根本分不清"真纹理"和"压缩伪影"**。同一段素材，8Mbps 与 120kbps 两版：

| 版本 | 肉眼看 | lap |
|---|---|---|
| 8Mbps | 发丝根根分明 | 60.6 |
| 120kbps | 糊成色块 | 54.6 |

差 6 分。因为压缩伪影（块效应 + 振铃）本身就是高频能量，把丢掉的细节"补"了回来。所以单看高频总量，好坏片长一个样。

### 试过、都失败的方案

| 方案 | 为什么不行 |
|---|---|
| 统一先高斯降噪 | 原图锐度掉 84%（470→74），低分辨率素材直接归零 |
| 减 20σ²（σ 用平坦块 std 估） | 406 片上把 σ 估成 1.5~2，干净片被扣成 0 |
| Sobel p99 | 抗噪好（噪14 只降 2.5%），但尺度不归一：同图 406 与 1620 差 2.1 倍 |
| 跨尺度能量比 | 能分纹理/伪影，但与分辨率强耦合（干净 1080 素材 1.1~2.7，干净 406 素材 3.0~4.0） |
| 帧差估噪 | 压缩噪声在时间上稳定（编码器复用静止块残差），测出来 σ=0 |
| 8px 块效应 | 被画面内容干扰：自家成片 1.567 高于 120kbps 压缩片 1.174 |
| 码率 bpp | 编码器效率差异太大：自家 1080 成片 0.032，比 406 压缩片还低 |

### 最终方案：三条判据各管一摊

**① BRISQUE（主判据，抓压缩损伤）**

`cv2.quality.QualityBRISQUE`，0-100，越低越干净。模型文件在 `scripts/models/`。

| 场景 | 分数 |
|---|---|
| 清晰 | 35.5 |
| 糊 0.8 / 1.5 / 2.5 | 48.0 / 62.2 / 71.6 |
| 干净 / 800k / 300k / 120k | 32.5 / 43.8 / 52.8 / 60.0 |

三条线全部单调 —— 这是手工指标做不到的。

**② 跨尺度能量比（只判"高频是不是噪点"）**

半尺度 lap ÷ 原尺度 lap。真纹理缩一半还在，噪点缩一半就没了。
实测：干净 3.5 / 压缩 2.3 / 噪点 σ14 0.22。

阈值卡在 **1.05**，不卡理论值 4.0——因为与分辨率强耦合，卡高了会误伤低分辨率干净素材。

**③ 噪声水平扣除（20σ²）**

用拉普拉斯响应幅值的 25 分位估 σ（噪声占满每个像素，纹理只占边缘，低分位由噪声主导）。
实测：406 原片估 0（不误扣）、加噪 σ3→3.51、σ8→8.42、σ14→14.04。

### 三条判据的分工

| 判据 | 管什么 | 不管什么 |
|---|---|---|
| BRISQUE | 压缩损伤 | 噪点（轻微噪声反而被判"更自然"：噪10 26.6 < 干净 36.9） |
| 跨尺度比 | 噪点主导 | 压缩（与分辨率耦合，判不了） |
| 20σ² 扣除 | 白噪声撑高的锐度 | 编码后的噪点（已非像素独立，σ 被低估） |

### 修完的效果

**素材模式**（`analyze(p, is_final=False)`，默认）：

```
8Mbps 62.3 > 800k 60.8 > 300k 53.3 > 120k 46.5
```

单调，方向正确。修前 120k 63.1、8M 62.4，几乎一样。

**成片模式**（`analyze(p, is_final=True)`）：不打画质折扣。自家成片从被误杀的 0.22 折恢复到 87.6 分。

### 为什么必须分成两套口径

BRISQUE 按**自然照片**统计建模。画面上的花字、贴纸、边框会被当成"结构异常"：

| 素材 | BRISQUE |
|---|---|
| 自家成片（带花字） | 78~94（比 120kbps 压缩片 62.4 还差） |
| 文字海报 | 70~83 |
| 真实拍摄画面 | 32~48 |

所以：
- **素材**用它判画质 ✓
- **成片**必须关掉（`is_final=True`）
- **画面里文字多**（菜单、价目表、海报）也会偏高 → 素材闸门里只警告不硬拒

## 仍然测不准的地方（说清楚，不装）

| 缺口 | 影响 | 现状 |
|---|---|---|
| **没有真实 1080 人像素材** | BRISQUE 与跨尺度比在 1080 实拍上准不准，没验证过。手头全是 406 压缩片和带花字的成片 | 待用户提供 `D:\QQ微信\` 原片 |
| 编码后的噪点 σ 被低估 | 噪10 实测 σ=1.4（真值 10），20σ² 扣不动 → 靠跨尺度比兜底 | 已缓解，未根治 |
| 跨尺度比与分辨率耦合 | 只能判"是不是噪点"，不能判压缩 | 压缩交给 BRISQUE |
| BRISQUE 对文字画面偏高 | 菜单/价目表特写会被警告 | 阈值设 75 只警告不拒 |
| 纯色背景测不出抖动 | 白墙棚拍只能标"未测" | 已如实标注，不假装很稳 |

## 运动镜头预测仍有偏差（已从 -28 改善到 -3）

统一口径后（预测也用 `score_final`）的实测对账：

| 段 | 预测 | 实测 | 偏差 |
|---|---|---|---|
| HOOK | 85.8 | 85.4 | -0.4 |
| BEFORE | 87.1 | 87.6 | +0.5 |
| PROCESS | 52.4 | 50.0 | -2.4 |
| PROCESS（运动大） | 52.5 | 39.0 | **-13.5** |
| PROCESS | 81.6 | 81.7 | +0.1 |
| AFTER | 81.6 | 81.7 | +0.1 |
| DETAIL | 85.8 | 76.6 | -9.2 |

修前是 -26~-28，主因之一就是预测用素材口径、实测用成片口径，两边不同尺子。现在大部分段落在 ±0.5 内。

剩下两段偏差大的是**运动剧烈的过程镜头**和**切分边界上的 DETAIL**——重编码对运动画面的损失是真实的，plan 层看不出来。这条仍然成立：**运动画面必须在成片上量，不能只看预测。**
