# 三道尺子出片质检

短视频出片前的三段式质检与自动返修。装一次，以后哪台电脑 `git clone` + 双击一个 bat 就能用。

---

## 三把尺子

片子剪完了，但不知道能不能发。三条硬性的尺子，各管一段，**绝不加权混成一个人看不懂的总分**：

| 尺子 | 问的问题 | 结果 |
|---|---|---|
| A 素材尺 | 这条素材能用吗 | 用 / 不用 |
| B 成品尺 | 这条片子好吗 | 0-100 + S/A/B/C/D |
| C 质检尺 | 播出去会出事吗 | A/B/C + 问题单 |

不合格会**照单返修**，不是重排碰运气：

- 开头不是钩子 → 换池里最高分镜头置顶
- 时长不够 → 拉非过程段的上限（过程段绝不拉长，短就是节奏武器）
- 节奏平 → 过程压到 0.62s，成果/细节放到上限
- 缺角色 → 池里补，没有就复用同一素材的不同入点

修完再评，连续两轮提升 <1 分就停，最多 6 轮。修不了的如实报"素材不足 / 需重拍"。

## 装

```bash
git clone -b san-chi-chu-pian https://github.com/dashuai6-6/jianying-automation.git san-chi-chu-pian
cd san-chi-chu-pian
```

> 网页直达：https://github.com/dashuai6-6/jianying-automation/tree/san-chi-chu-pian
> 不在默认分支上，记得带 `-b san-chi-chu-pian`；不带就拉到剪映老技能那份。

双击 **`install-skill.bat`**。它会装依赖、把技能复制到技能目录、跑一遍自检。

自检必须看到 `quality True` 和一个数字分数：

```
opencv 4.x | quality True | BRISQUE 100.0
```

**如果是 `None`，画质判据是失效的**——流程还会跑，分数还会出，但结论是假的。别拿它去发片。

## 更新

双击 **`update-skill.bat`**，拉最新 + 重装。

## 用

不用记命令，直接说人话：

| 你说 | 触发什么 |
|---|---|
| 「这几条素材能不能用」 | 尺子 A 体检，出可用/弃用清单 |
| 「帮我剪一条 20 秒探店」 | 编排 → 五维评审 → 自动返修到合格 |
| 「这条成片能不能发」 | 尺子 B + C，出总分和事故单 |
| 「剪完检查一下」 | 全流程，出报告 |
| 「按 128 BPM 卡点」 | 半拍网格排时长，报最大偏差毫秒 |

## 硬拒线（尺子 A）

| 项目 | 线 | 为什么 |
|---|---|---|
| 源宽 | < 720px | 输出 1080 要放大，发丝必糊 |
| 抖动 | > 3.0 %W/s | 肉眼可见手抖，救不回 |
| 甩镜 | 任意 | 帧间位移过大，拼不上 |
| 细节锐度 | < 25 | 已按 `lap × (实测宽/640)` 尺度归一 |

## 依赖

- Python 3.10+
- `opencv-contrib-python-headless`（**必须是 contrib 版**，`cv2.quality` 里的 BRISQUE 只在 contrib 里）
- `numpy`
- `ffmpeg` 命令行

## 已知边界

- 阈值主要在 406~1080 压缩片和合成素材上标定，能证明"有区分度"，还没在真实 1080 人像原片上验过绝对分准不准。
- 只负责判和改参数，输出的是剪辑 plan（每段 `path/src_in/dur/speed/out`），渲染交给剪映或另配的渲染器。
- 返修改时长用的是节奏判断、不是拍点判断，所以会偏离半拍网格，`loop()` 会如实报偏差毫秒。
